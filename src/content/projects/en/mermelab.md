title: AppMermeLAB
tagline: An ERP for a jam-making lab
problem: >-
  A small artisanal production lab kept recipes, inventory and waste on paper.
  A badly calculated batch cannot be fixed afterwards: it is lost entirely,
  with the fruit and the sugar already spent.
highlights:
  - Four modules —inventory, production, waste and sales— around an engine that decides whether a batch is viable given the inventory on hand.
  - Compares Brix degrees against each recipe's range and warns when the measured value falls outside it.
  - Contrasts expected waste against actual waste on every cook, so recipes can be adjusted with data instead of intuition.
  - "Every calculation in decimal precision, not floating point: Brix degrees do not tolerate it."
  - Built as part of COIL 2026, a cooperation between UTP and the Universidad del Valle de Guatemala.
stack:
  - Python
  - Flask
  - SQLAlchemy
  - SQLite
repo: https://github.com/Jesus41844/AppMermeLAB
footnote: >-
  This is a desktop application that is installed and run locally, not a
  website, which is why it has no public demo. Built with students from the
  Universidad del Valle de Guatemala as part of COIL 2026.
